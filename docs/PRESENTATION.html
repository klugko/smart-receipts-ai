Smart Receipts AI

API-Based OCR System for Receipt Information Extraction

FastAPI + Tesseract OCR + Ollama/Llama 3.2

Solution Overview

Objective

Build a containerized API to extract structured information from scanned PDF receipts using open-source models for data privacy compliance.

Key Features

  • RESTful API with FastAPI
  • Multi-engine OCR support (Tesseract, EasyOCR)
  • Open-source LLM extraction (Ollama/Llama 3.2)
  • Service Provider Database for data enrichment
  • Multi-language support (EN, DE, FR, ZH)
  • Comprehensive evaluation framework

OCR Engine Comparison

Engine Strengths Best For
Tesseract Fast, multi-language, lightweight Standard receipts, high-quality scans
EasyOCR Better layout handling, GPU support Complex layouts, rotated text

Preprocessing Impact

  • Contrast enhancement: +15% accuracy on low-quality scans
  • Deskewing: Essential for rotated receipts
  • Denoising: Reduces OCR errors on scanned documents

Service Provider Database Proposal

Purpose

Improve extraction quality by matching against known providers and validating extracted data.

Features

  • VAT Number Lookup: Exact match for 100% confidence
  • Fuzzy Name Matching: RapidFuzz for approximate matches
  • Data Enrichment: Fill missing fields from database
  • Learning Loop: Auto-add new providers from extractions

Database Schema

providers ( id, vat_number (unique), name, name_variations, address, country, phone, email, category, confidence_score, extraction_count )

Benefits

  • Reduces OCR errors through validation
  • Provides consistent provider naming
  • Enables category-based processing rules

Current Limitations

Technical Limitations

  • Handwritten receipts: Limited OCR accuracy
  • Non-Latin scripts: Requires additional language packs
  • Very poor quality scans: May fail extraction
  • Complex table layouts: Item parsing may be incomplete

Data Limitations

  • VAT formats: Not all countries fully validated
  • Currency detection: Relies on explicit symbols/codes
  • Date formats: Regional variations may cause errors

Processing Limitations

  • Large PDFs: Memory usage increases with page count
  • Concurrent requests: Limited by Ollama capacity
  • Cold start: First request has model loading delay
  • CPU mode: Significantly slower without GPU

Mitigation Strategies

  • Image preprocessing pipeline
  • Fallback to multiple OCR engines
  • Confidence scoring for output validation
  • Model warm-up on startup
